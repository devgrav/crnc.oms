### Описание
Cистема для управления заказами в виртуальной производственной компании CRNC. 
Позволяет отследить жизненный цикл заказа на производство изделия от его формирования до выполнения работы и доставки клиенту. 
Предполагает следующие модули: безопасность, продажи, производство, уведомления. Дополнительные функции: прием платежей, доставка, интеграция с внешним сервисом email.

Реализован модуль безопасности в виде авторизации и администрирования пользователей.
В базовом варианте реализован модуль уведомлений.

Частично реализован frontend в виде spa и backend модуля продаж для управления заказами и клиентами.
Планируется полная реализация модуля продаж и модуля управления производственными работами вместе с frontend.
Использует Asp.Net Core, Mongo Db, PostgreSQL на backend и React.js, TypeScript, Semantic UI на frontend.

### Модуль безопасности
Модуль включает в себя авторизацию, управление ролями пользователей и управление пользователями в виде CRUD операций. 
Создание/редактирование пользователя включает в себя изменение персональных данных, учетных данных, добавление фотографии.   
Полный список действий с примерами данных доступен по соответсвующему swagger endpoint после запуска.
Модуль использует кеширование данных пользователей в памяти сервиса через `IMemoryCache` из `ASP.NET Core`, так как они редко изменяются и могут быть изменены только через API этого модуля, кеш обновляется после изменения, удаления или создания пользователей.
API по управлению пользователями требует аутентификации, JWT-токен можно получить в этом же API.
Технологии: ASP.NET Core + Mongo

### Модуль продаж
Модуль включает в себя управление заказами, просмотр и фильтрацию списка заказов, создание и редактирование заказов с описанием требуемой работы, 
изменение статуса заказа и его конвертацию в работу на производство.
Создание и редактирование клиентов.
В процессе реализации, доступно создание и редактирование заказов со сменой статуса и отправкой уведомления пользоватеям с ролью `Main manager`
В рамках дополнительных функций может быть реализован сервис приема платежей, который используется при учете схемы оплата заказа, в базовом варианте оплата учитывается в ручном режиме.
API требует аутентификации, JWT-токен можно получить через `CRNC Oms Security API`.
Технологии: ASP.NET Core + PostgreSQL

### Модуль производства
Модуль включает в себя управление работами на прозводство, изменение статусов работы до ее выполнения. В рамках дополнительных функций может быть реализована панель, которая в режиме реального времени отражает статусы по работе.

### Модуль уведомлений
Включает в себя отправку уведомления через разные каналы, email/push уведомления для сотрудников в зависомости от изменений в системе, к примеру, при смене статусов заказов и работ.
Отправка уведомлений реализована через Gateway/Ambassador микросервис `Crnc Oms Notification Gateway API`, он позволяет отправлять уведомления в различные каналы относительно получателя уведомления, к примеру пользователи системы получают уведомления в email и push каналы, использует отдельные микросервисы для email `Crnc Oms Email Notification API` и push `Crnc Oms Push Notification API`. 
Отправка уведомлений интегрирована в процесс создания заказа, если изменился статус заказа, то все пользователи с ролью `Main Manager` получат push-уведомление, вместо отправки email сервис просто пишет сообщение в консоль. Для тестирования push-уведомлений сделан отдельный клиент, который запускается в своем контейнере и пишет полученное push-сообщение в консоль. 
Отправку тестовых сообщений можно сделать через `Crnc Oms Sales API`, изменив статус заказа методом Edit или через `Crnc Oms Notification Gateway API`, вызвав тестовый метод отправки.
API требует аутентификации, JWT-токен можно получить через `CRNC Oms Security API`.
Полный список действий с примерами данных доступен по соответсвующему swagger endpoint после запуска.
Технологии: ASP.NET Core, SignalR. Дополнительно будет добавлена очередь на RabbitMq, и, возможно, сторонний email-сервис.

### Запуск
Backend для всей системы можно запустить через docker-compose из корня репозитория:

###### Для запуска:

`docker-compose build`

`docker-compose up`

В случае ошибок удаляем и заново делаем `up`

###### Для удаления:

`docker-compose down`

После запуска api модулей будет доступно через Swagger UI:

Безопасность: [CRNC Oms Security API](http://localhost:8090/swagger).

Продажи: [CRNC Oms Sales API](http://localhost:8091/swagger).

Шлюз уведомлений: [CRNC Oms Notification Gateway API](http://localhost:8100/swagger).

Уведомления по email: [CRNC Oms Email Notification API](http://localhost:8104/swagger).

Уведомления push: [CRNC Oms Push Notification API](http://localhost:8107/swagger).

Тестовый push-клиент `notification-push-client` не имеет api и просто пишет сообщения в консоль контейнера.
